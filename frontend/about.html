Research question

Can uncertainty-aware AI make citizen biodiversity data more trustworthy?

“Does an explicit abstention and image-quality stage reduce overconfident species labels compared with a plain top-1 classifier, without making the tool unusable?”

The project does not claim to answer this with a large field study. It builds the artefact needed to investigate it: a model with a validation-selected abstention threshold, quality gates, geographic plausibility checks, a human review queue, and honest UI copy. The accompanying evaluation reports top-1/top-3 accuracy and selective-prediction coverage on a held-out split of a small demonstration dataset.

What was built

Four connected subsystems.

1 · Identification pipeline

Upload validation, EXIF stripping, brightness/sharpness checks, MobileNetV3-small inference, temperature scaling, top-3 output and abstention.

2 · Observation workflow

Consent-gated storage, anonymous session ownership, sensitive-species coordinate obscuration, deletion, reporting and admin review.

3 · Tourism catalogue

70 seeded Odisha records across 14 categories, provenance fields, data-gap reporting, corrections and suggestions.

4 · Discovery tools

Search and filters, unified map, favourites, manually ordered itineraries and a reviewer console.

Architecture

One FastAPI origin, no external services required at runtime

The frontend is static HTML/CSS/JS served by the same FastAPI app. All libraries and fonts are vendored so the app works offline except for OpenStreetMap tiles.

Data sources & licensing

What is sourced, and what is curated

Tourism coordinates
OpenStreetMap / Photon geocoding, ODbL. 52 of 70 seed records have coordinates; the rest deliberately have no pin.
Tourism text
Project-curated seed descriptions from public reference material. Provisional until a reviewer checks the source.
Species taxonomy
Curated catalogue cross-checked against the GBIF backbone. Descriptions are project-written, CC BY-SA 4.0.
Species photographs
Training images are recorded with source and licence in the model card and dataset manifest. No tourism photographs are used; category artwork is CSS + Lucide icons.
Basemap tiles
OpenStreetMap standard tiles, © OpenStreetMap contributors, ODbL. Tile usage is for academic demonstration, not high-volume production.

Model card

Installed models and measured performance

These values are read live from the local model registry. If a model is not installed, BioTrace says so and returns an “unavailable” decision.

Try a prediction
Do not interpret model scores as field-validated accuracy. The demonstration models cover a small, curated class list. They cannot identify every Odisha plant or bird, and they may be confidently wrong on look-alikes, juveniles, hybrids, damaged specimens or out-of-distribution photos. Metrics are only reported when a real held-out evaluation has been run.
Evaluation methodology

What the numbers mean

Stratified split — training, validation and test sets are disjoint by image, with the class distribution reported.
Top-1 and top-3 accuracy — measured on the held-out test split, not on training data.
Selective prediction — coverage and accuracy above the abstention threshold are reported together, so a high threshold cannot hide low coverage.
Calibration — validation-set temperature scaling is applied and the fitted temperature is stored in the model card.
Known gap — the demo dataset is small and not a substitute for a field survey or expert-curated regional dataset.

Decision policy

How a prediction becomes a decision.

1 · Quality gate

Reject images below minimum resolution, extremely dark or too blurry. No prediction is attempted.

2 · Model availability

If no checkpoint exists, return “unavailable” with installation instructions. Never substitute a fake label.

3 · Confidence threshold

If top confidence is below the validation-selected threshold, return “review” and explain why.

4 · Margin and geography

A very small top-two margin or an implausible district also triggers “review”, even if confidence is high.

5 · Human confirmation

Accepted predictions remain preliminary. Saved observations start as pending and require reviewer action.

Ethics & privacy

Small data, clear boundaries

No accounts, no tracking

The app uses an anonymous browser session identifier, hashed server-side. There are no analytics scripts, advertising pixels or third-party trackers.

Sensitive species

Species with an endangered or vulnerable status are flagged, and their coordinates are obscured before being returned to any client or map.

Image handling

Uploads are re-encoded, EXIF metadata is stripped, and files are stored locally. Observation images are served read-only. Users can delete their own records.

Consent first

Prediction works without saving. Saving requires explicit consent, and the UI explains that the record becomes publicly visible as pending.

No fabricated tourism facts

Hours, fees, contacts and accessibility are shown only when recorded. Otherwise the interface says “Not verified — information unavailable”.

Admin separation

The reviewer console uses environment-configured credentials and short-lived signed bearer tokens. Public users cannot change verification status.

Known limitations

What this project does not do

  • It is not a complete catalogue of Odisha tourism; 70 seed records are a demonstration subset.
  • It does not provide live opening hours, ticket prices, contacts or route planning.
  • It does not verify AI predictions automatically. Every saved observation needs human review.
  • It does not cover all Odisha flora and avifauna; only the classes in the model card are in scope.
  • It does not replace expert taxonomic identification, especially for cryptic or look-alike species.
  • It does not use user accounts, cloud sync or multi-device persistence.
  • It is not hardened for public internet deployment without additional security review.
  • The SQLite database and local file storage are suitable for a demo, not high concurrency.
Future work

How the project could grow

Field evaluation with botany and ornithology reviewers, including inter-rater agreement.
A larger, regionally balanced dataset with explicit geographic and seasonal splits.
Out-of-distribution detection rather than relying only on softmax confidence.
Optional expert accounts with auditable review history and role-based permissions.
Tourism data ingestion from official district and ASI sources with scheduled re-verification.
Accessibility audit of the interface with screen-reader and keyboard-only users.
